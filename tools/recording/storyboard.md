# 录屏分镜方案 · 也是一段"AI coding 惊喜瞬间"

> 本文档既是录屏分镜的落地方案,也是项目开发过程中一个值得留住的 moment 素材:
> AI 把三个表面问题归因到**一个根因**,再用**一张分镜表**把其中两个同时治掉。
> 后续讲"AI coding 里让我惊喜的瞬间"时,直接用这一段。

## 1. 文档定位

- 不进 `design/` 里程碑,是 `tools/recording/` 下的内部录屏工程文档(与 README 并列)。
- 描述:从"字幕切片+错位+底色不一致"三个问题,到"统一 storyboard"方案。
- 状态:**方案已与用户对齐,待落地。**

## 2. 起因(用户提出的三个问题)

1. 字幕被断句,每条不是完整一句话。
2. 字幕有时和画面内容对不上,想让"每页画面"与"字幕"强相关。
3. 字幕窗黑底、代码运行窗白底,两者不一致。

## 3. 根因诊断

| 症状 | 根因 | 为什么 |
| --- | --- | --- |
| 字幕切半句 | `subtitle_player.py` 的 chunker 按"≤30 字硬切" | 不按句末标点断,只为控宽,自然劈开 `OpenTelemetry` 这类词 |
| 字幕与画面错位 | **画面步表和字幕是两条独立时间线** | 画面时间写在 bash;字幕按"字数比例"在 python 自动排,互不知道"哪句配哪页" |
| 底色不一 | `create_sub` 设了 `Pro` 黑底,`create_demo` 没设 profile 走默认白底 | 两个窗口用了不同配色 |

关键发现:**症状 1 和 2 同一个根因**——字幕是被独立"按字数自动排版"的,既不知道句子边界(→切半句),也不知道画面在干什么(→错位)。所以它们应该一起治。

## 4. 方案:统一 storyboard(单一数据源)

废弃两条独立时间线,改成**一张分镜表当唯一真相**。每一行 = 一个 beat:

```text
时间码 | 画面步(或 HOLD) | 该页对应的一整句字幕(或 HOLD)
```

在同一个 beat 同时推进画面和字幕 →

- 每条字幕天然是**一整句**(问题1),因为人写的就是完整句子,不再机器硬切;
- 字幕说的**就是画面上那份内容**(问题2),因为每个 beat 是"画面步×字幕句"一起写的;
- 单一数据源,画面/字幕/预览三处同源,**不再漂移**。

一个精妙点:画面和字幕允许**各自 HOLD**。在 S4 里四件套命令(fmt/test/clippy/build)会轮播四个画面,但只配**一句**字幕"然后强制跑四件套……"贯穿;相反某页画面停留时也可以换两三句字幕。靠 pic / sentence 取 `HOLD`/具体值即可表达任一组合,所以"一句对一页"和"一句跨多页"都自然支持。

## 7. 落地形态(单一数据源的实现)

- `subtitle_player.py` 持有 `STORYBOARD`(`[(sec, pic, sentence), ...]`,pic/sentence 可为 `"HOLD"`)。
- 字幕驱动:遍历 STORYBOARD,在 `sentence != HOLD` 的 beat 把那**整句**推进字幕窗(不再 chunk)。
- 画面驱动:`record-tracelens.sh` 的 `run_timeline` 不再手写 `at N; play X`,改为消费 `subtitle_player.py --timeline`(输出 `sec pic`)生成,bash 端零漂移。
- `preview_map.py` 也从 STORYBOARD 生成 → 对位图自动与新分镜同源。
- 三处同源 → 改一句字幕只动 STORYBOARD 一行。

## 8. 作为"AI coding 让我惊喜的瞬间"叙事稿

> 我让 AI 改字幕的三个毛病:字幕被切半句、和画面对不上、两个窗底色不一。
> 它没有闷头各打各的补丁,先给了一张诊断表,指出**前两个其实是同一个根因**——字幕是被独立"按字数自动排"的,既不知句界也不知画面,才会又切半句又错位。
> 然后它提了一句让我眼前一亮:"把两条时间线塌成一张分镜表,每一行 = 时间 × 画面 × 一整句字幕,画面和字幕在同一个 beat 一起推进。"——三个问题里,光这一招就把两个一起治了,顺带还消除了以后画面和字幕漂移的可能。剩下底色那个独立小问题,加一行 profile 解决。
> 我事后想,它让我惊喜的不是"写得多快",而是**抓住了"两个症状同根"这件事**,用一个比补丁更小的结构改动一次性收掉。这是 AI 协作里少见的、像工程老手一样的判断。
